# 검토 기준 (엔진 판정과 같은 기준)

블라인드 검토 JSON 필드와 반려 조건이다. `review-brief.md`에 같은 지시가 들어 있다.

| 필드 | 의미 | 반려 조건 |
|---|---|---|
| `answerIndex` | 검토자가 고른 정답 번호(1~5) | 의도 정답과 다르면 반려 |
| `ambiguity` | none / minor / major | major면 반려 |
| `curriculumIssues` | 교과 오류, 내부 모순, 제시하지 않은 자료, 범주 오류, 법·제도 사례 성립 문제 | 하나라도 있으면 반려 |
| `answerGivenAway` | 제시문이 정답 개념명·정의를 그대로 알려 줌 | true면 반려 |
| `trivialStatements` | 개념 없이 제시문 값만 읽어 판정되는 진술 표지 | 3점은 1개 이상, 2점은 2개 이상이면 반려 |
| `dataFreeStatements` | 제시문을 가려도 교과 개념 암기만으로 판정되는 진술 표지(스킬 검토에만 있음) | 3점은 2개 이상, 2점은 3개 이상이면 반려 |
| `perceivedDifficulty` | easy / moderate / hard | 3점 문항이 easy면 반려. 초고난도는 `statementAnalysis`가 없을 때만 hard가 아니면 반려 |
| `statementAnalysis` | 초고난도만: 진술마다 {label, steps}. steps = 꼭 필요한 서로 다른 판단(단서 연결·개념 판별·계산/비교) 수 | 2 미만인 진술이 있으면 반려 |
| `eliminationShortcut` | 초고난도만: 일부 진술만 판정해 소거로 정답이 정해지는 길 | true면 반려 |
| `stemIssues` | 발문이 한 번에 읽히지 않는 문제(자료 나열, 수식어 겹침, 조건 둘 이상·기준 여럿) | 하나라도 있으면 반려(발문만 고치기) |
| `mixConceptsUsed` | 개념 고정 계획의 엮을 개념 중 실제로 판정에 필요했던 것 | 빠진 개념이 있으면 반려 |
| `reasoning` | 풀이 근거 | — |

반려 뒤 다시 쓰는 방식(`fix`)은 반려 사유에 따라 정해진다.
- 정답 불일치, `ambiguity: major`: 대체 명세로 새로 쓴다(replan).
- 그 밖의 반려: 같은 명세에서 앞 시도 문항을 고친다(repair).

검토자는 "통과시키려고" 읽지 않는다. 결함을 찾는 것이 목적이다. 특히:
- 정답이 하나로 확정되는가, 다른 선지도 옳을 수 있는가, 정답 조합이 선지에 있는가
- 판정에 필요한 사실(상시 근로자 수, 계약 당사자, 요건 충족 여부)이 모두 제시되었는가
- 급여·지원금의 수급 주체와 신청 기관이 교과서와 같은가

# 평가원 문체 (엔진이 일부 자동 보정)

- 서술문 과거형은 "하였다·되었다·하여"(엔진이 "했다·됐다·해서"를 자동 보정, 대화 발화는 구어 유지)
- 어휘는 교과서·기출의 표준어: 대화 발화도 말투만 해요체이고 낱말은 시험지 어휘("접었다→택하지 않았다", "라이더→배달원", "신나다→즐겁다", "자격증을 따다→취득하다", "밀린 임금→체불 임금"). 기출에 없는 속어·유행어·과장 표현은 쓰지 않는다(엔진 check가 일부 목록을 즉시 반려)
- 문서형 자료(보고서·안내문·상담 기록 등)는 ■ 소제목 + • 개조식 줄(~함/~임, 명사 끝)
- 서술 문장은 25~45자, <보기>·선지는 30~35자 안팎, "~한다/~할 수 있다/~에 해당한다"로 끝맺음
- 용어 인용 ‘ ’, 말 인용 “ ”, 법률명 ｢ ｣, 날짜 "2024년 12월 10일", 금액 "36,000원·60만 원", 인물 "A 씨"
