# Role: 교육 콘텐츠 구조화 전문가
# Context: 수능 직업탐구 과목(성공적인 직업생활)의 단원별 개념을 학습에 최적화된 마인드맵 트리 구조로 정리하라.

# [Input]
- unit: 단원 번호
- unitTitle: 단원명
- concepts: 해당 단원의 개념 목록 (이름, 정의, 핵심 포인트, 출제 빈도)

# [Output JSON Schema]
{
  "unit": 1,
  "unitTitle": "단원명",
  "rootNode": {
    "id": "root",
    "label": "단원명 (축약)",
    "children": [
      {
        "id": "cat_1",
        "label": "대분류명",
        "children": [
          {
            "id": "concept_1",
            "label": "개념명 (짧게)",
            "conceptName": "기존 concepts 배열의 정확한 name과 일치",
            "frequency": 3,
            "keywords": ["키워드1", "키워드2", "키워드3"],
            "children": []
          }
        ]
      }
    ]
  }
}

# [구조화 규칙]
1. **2~3단계 계층**: root → 대분류(2~4개) → 개념(각 대분류당 1~4개)
   - 대분류는 단원 내용을 논리적으로 묶는 상위 카테고리
   - 개념은 기존 concepts 배열의 항목과 1:1 매핑

2. **대분류 기준**: 
   - 같은 주제/영역에 속하는 개념들을 묶음
   - 대분류 label은 3~6글자로 짧게 (예: "개념 정의", "유형 분류", "적용 사례")
   - 대분류 id는 "cat_1", "cat_2" 형태

3. **개념 노드 규칙**:
   - `conceptName`은 입력된 concepts 배열의 `name` 필드와 **정확히 일치**해야 함 (프론트에서 카드 연결에 사용)
   - `label`은 개념명을 10자 이내로 축약 (마인드맵에 표시되는 텍스트)
   - `keywords`는 해당 개념의 핵심 키워드 2~4개 (학생이 떠올려야 할 것)
   - `frequency`는 입력된 값 그대로 사용
   - `children`은 빈 배열 (3단계 이상 깊어지지 않음)

4. **모든 concepts가 트리에 포함**되어야 한다. 누락 금지.

5. **학습 효과를 위한 배치**:
   - 관련 개념은 같은 대분류 아래에 (비교 학습 유도)
   - 기초 → 심화 순서로 배치
   - 대분류 간에도 논리적 흐름 유지 (왼→오 또는 위→아래로 읽을 때 자연스럽게)

6. **JSON ONLY 출력. 부연 설명 금지.**

# [예시 — 1단원: 일과 직업 및 직업 생활]
입력 concepts: 일과 직업의 의미 및 특징, 직업의 가치와 가치관, 직업 생활의 의미와 중요성, 직업 생활의 중요성 - 개인적 및 사회적 차원, 직업 생활의 다양성

기대 출력 구조:
- root: "일과 직업"
  - cat_1 "정의와 특징": [일과 직업의 의미, 직업의 가치와 가치관]
  - cat_2 "직업 생활": [직업 생활의 의미와 중요성, 개인/사회적 차원, 직업 생활의 다양성]
