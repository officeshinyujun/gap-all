2. ①~⑤ 선택지는 보기의 진위 조합을 인코딩한 결과로 구성한다.
3. 표준 인코딩 형식: ① ㄱ, ㄴ  ② ㄱ, ㄷ  ③ ㄴ, ㄷ  ④ ㄴ, ㄹ  ⑤ ㄷ, ㄹ

5. 오답 선택지는 최소 하나의 거짓 보기를 포함하거나 참인 보기를 누락해야 한다.
6. ①~⑤를 독립적인 자유 서술 선지로 생성하지 마라. 조합형 문항의 선택지는 반드시 보기 조합이다.

9. `render_ready.combo_block.items`는 반드시 4개이며 key는 순서대로 ㄱ, ㄴ, ㄷ, ㄹ이어야 한다.
10. 각 item의 `text`에는 실제 보기 진술문을 채워라. 빈 문자열, placeholder, 메타 지시문 금지.
11. `options_list`는 `combo_block.items`의 진위 조합만을 인코딩한 결과여야 하며, 독립적인 서술 선지를 생성하지 마라.

# [비조합형 렌더링 규칙]
Blueprint의 `item_structure.item_family`가 아래 중 하나이면 해당 family의 규칙을 반드시 따른다.

1. `single_selection`
- 발문은 반드시 하나의 독립된 정답 후보를 고르게 해야 한다.
- 5개 선지는 반드시 같은 범주의 후보여야 한다. (예: 모두 시스템명, 모두 관리 기법명, 모두 입지 유형명, 모두 공정 단계명)
- 일부 선지는 기술 개념명이고 일부는 긴 판단문인 혼합 구성을 금지한다.

2. `direct_statement`
- 기사, 보고서, 기술 저널, 점검표, 설비/생산 자료를 직접 읽어야만 답할 수 있게 하라.
- stimulus_data를 제거해도 답할 수 있는 문제는 금지한다.
- 발문과 선지는 반드시 자료 속 같은 판단 축(시스템 판별, 공정 해석, 기법 판단, 재해 원인, 분류 체계 등)을 공유해야 한다.

3. `blank_workflow`
- `(가)`, `(나)` 또는 단계/절차/흐름의 특정 위치와 선지가 직접 대응해야 한다.
- 일반 독립 선지 문제처럼 만들지 마라. 선지는 반드시 빈칸 단계의 내용, 기능, 목적, 다음 단계 조건 중 하나를 묻는 구조여야 한다.

# [exhaustive_subset 렌더링 규칙]
Blueprint의 `choice_encoding_type`이 `subset_exhaustive`인 경우:
1. combo_block.items는 3개(ㄱ, ㄴ, ㄷ)로 구성한다. ㄹ은 생략.
2. options_list는 단일 항목(예: "ㄱ"), 2개 조합(예: "ㄱ, ㄴ"), 3개 전체(예: "ㄱ, ㄴ, ㄷ")를 혼합하여 정확히 5개로 구성한다.
3. 정답은 참(truth=true)인 보기를 '있는 대로' 모두 포함한 선지다.
4. 오답은 참인 보기를 누락하거나 거짓 보기를 포함한 조합이다.
5. 발문은 "...적절한 것만을 <보기>에서 있는 대로 고른 것은?" 형태를 사용한다.

# [label_matching 렌더링 규칙]
Blueprint의 `item_family`가 `label_matching`인 경우:
1. combo_block.items에 보기 항목(ㄱ~ㄹ, 3~4개)을 배치한다.
2. options_list는 "(가)-ㄱ, (나)-ㄴ, (다)-ㄷ" 형태의 라벨-보기 매칭 조합 5개로 구성한다.
3. 정답은 label_answer_map과 정확히 일치하는 매칭 조합이다.
4. stimulus_data에는 (가), (나), (다) 빈칸이 포함된 표/연표/분류도를 배치한다.

# [pair_selection 렌더링 규칙]
Blueprint의 `item_family`가 `pair_selection`인 경우:
1. combo_block은 생략한다 (보기 블록 없음).
2. options_list의 각 선지는 "축1값, 축2값" 형태의 쌍으로 구성한다.
3. 5개 선지는 pair_axes의 두 축 후보 값을 교차 조합하여 생성한다.
4. 정답 쌍만이 자료 근거에 의해 유일하게 옳아야 한다.
5. 발문에 두 축의 이름이 명시되어야 한다: "...직업 윤리와 기업가 정신으로 가장 적절한 것은?"

# [Implementation Rules]
1. **Full Coverage (수량 엄수):** 입력된 Blueprint 배열에 포함된 모든 설계도를 단 하나도 누락하지 말고 순차적으로 집필하여 결과 배열에 포함하라.
2. **Metadata Tagging:** 각 문항 객체 상단에 위 Output Schema의 `metadata` 필드를 빠짐없이 채워라. `recommended_template`도 반드시 포함하라.
3. **options_list 필수:** `render_ready.options_list`는 반드시 정확히 5개의 문자열 배열이어야 한다. 누락하거나 5개 미만이면 시스템 오류로 간주한다.
4. **correct_answer 필수:** `correct_answer`는 1~5 사이의 정수여야 한다. 반드시 최상위 필드로 포함하라.
5. **Blueprint 판단 계획 준수:** Blueprint에 `judgment_map`과 `choice_encoding_plan`이 있으면, 해당 진위 배정과 조합 인코딩을 그대로 따라 렌더링하라. Step 2에서 독립적으로 논리를 재발명하지 마라. 조합형 문항이면 반드시 이 판단 계획을 `render_ready.combo_block`과 `options_list`에 모두 반영하라.
6. **Answer Concealment (정답 은닉):** `stimulus_data`만 보고 정답을 바로 알 수 있으면 안 된다. 자료는 추론의 단서를 제공할 뿐, 정답 자체를 노출해서는 안 된다.
7. **TPL별 정답 은닉 규칙:**
   - `TPL_SEQUENTIAL_WORKFLOW`: 반드시 아래 두 유형 중 하나만 선택하여 일관되게 설계하라.
     [유형 A: 빈칸 채우기형] steps 중 1~2개에만 is_missing: true 설정.
     [유형 B: 내용 이해형] 모든 steps에 is_missing: false 설정.
     [절대 금지] 순서 배치를 요구하는 발문.
   - `TPL_COMPARATIVE_MATRIX`: 표-발문 연동 필수. 표만 보고 정답을 바로 알 수 없도록 설계.
   - `TPL_CASE_DIAGNOSTIC_FRAME`: 체크리스트 항목이 선지와 1:1 대응되지 않도록 하라.
   - `TPL_CONVERSATIONAL_FLOW`: 대화 내용에서 정답이 직접 언급되지 않도록 하라.
8. **Hyper-Detailed Explanation (초정밀 해설):** `explanation` 필드에 정답 근거와 각 오답 설계 근거를 상세히 기술하라.
9. **Strict Grounding (폐쇄 참조):** 오직 주입된 `units`의 `text_payload` 정보만을 근거로 삼는다. 외부 지식이나 상식의 개입을 철저히 차단하라.
10. **Standard CSAT Vocabulary:** 모든 텍스트는 수능 기출 표준 어휘를 사용하라.
11. **JSON ONLY:** 부연 설명 없이 유효한 JSON 배열 코드 블록만 출력하라.
12. **Zero Placeholder (플레이스홀더 금지):** stimulus_data, options_list, question_stem의 모든 필드에는 반드시 구체적이고 완성된 실제 콘텐츠만 들어가야 한다.
13. **Family Coherence (비조합형 정합성):** `single_selection`, `direct_statement`, `blank_workflow`는 각각의 구조 규칙을 반드시 지켜라. 비조합형은 단순히 '조합형이 아닌 아무 문제'가 아니다.

# [수치 계산 규칙 — 공일]
이 과목의 실제 수능 문항은 생산·품질·재고·공정 관련 수치 계산을 포함한다. 아래 계산 규칙을 반드시 숙지하고 문항에 적용하라.

1. **손익분기점(CVP 분석) 계산**
   - 손익분기점 판매량 = 고정비 ÷ (판매단가 - 변동비)
   - 손익분기점 매출액 = 고정비 ÷ 공헌이익률(=(판매단가-변동비)÷판매단가)
   - 계산 예시: 고정비 1,000만원, 판매단가 5만원, 개당 변동비 3만원
     → 공헌이익 = 2만원, BEP 판매량 = 1,000÷2 = 500개, BEP 매출액 = 500×5 = 2,500만원
   - 목표이익 달성 판매량 = (고정비 + 목표이익) ÷ 공헌이익
   - 안전한계 = 실제 매출 - BEP 매출

2. **관리도(품질관리) 계산**
   - 중심선(CL) = 전체 시료 평균(𝑥̄)
   - 관리상한(UCL) = 𝑥̄ + A₂R̄  (A₂는 시료 크기별 계수)
   - 관리하한(LCL) = 𝑥̄ - A₂R̄
   - 𝑅 관리도: 중심선 = R̄, UCL = D₄R̄, LCL = D₃R̄
   - 계산 예시: 시료 5개씩 20회 측정, 평균 50.2, R̄=4.2
     → n=5일 때 A₂=0.577 → UCL = 50.2+(0.577×4.2)=52.62, LCL = 50.2-(0.577×4.2)=47.78
   - 공정 능력 지수 Cp = (USL-LSL) ÷ 6σ
   - Cpk = min((USL-𝑥̄)÷3σ, (𝑥̄-LSL)÷3σ)
   - Cp≥1.33: 공정 능력 충분, Cp<1.0: 공정 능력 부족

3. **경제적 주문량(EOQ) 계산**
   - EOQ = √(2DS/H)
     (D: 연간 수요량, S: 1회 주문비용, H: 연간 단위당 재고유지비)
   - 연간 주문 횟수 = D ÷ EOQ
   - 연간 총 재고비용 = (EOQ÷2 × H) + (D÷EOQ × S)
   - 계산 예시: 연간 수요 1,200개, 1회 주문비 30,000원, 단위당 연간 유지비 2,000원
     → EOQ = √(2×1,200×30,000÷2,000) = √36,000 = 189.7 → 약 190개
     → 연간 주문 횟수 = 1,200÷190 ≈ 6.3회
   - 재주문점(ROP) = 1일 평균 수요 × 조달기간(일)

4. **표준화·KS 규격 판단**
   - KS 규격 적용 범위: 제품의 종류·형상·치수·품질·시험방법 등
   - KS 표시 허가: KS 인증을 받은 제품에만 KS 마크 표시 가능
   - 계산 예시: KS 규격에서 볼트 M10×1.5의 나사 피치 1.5mm 확인
   - 공차 계산: 기본 치수 ± 허용차 범위 내에 있는지 판단
   - 계산 예시: ø50h7(0, -0.025) → 49.975~50.000mm 범위 내에 있어야 합격

5. **가동률·효율 계산**
   - 가동률 = (실제 가동시간 ÷ 계획 가동시간) × 100
   - 시간 가동률 = (부하시간 - 정지시간) ÷ 부하시간 × 100
   - 성능 가동률 = (처리수량 × 사이클타임) ÷ 가동시간 × 100
   - 양품률 = (양품수량 ÷ 총 처리수량) × 100
   - 종합설비효율(OEE) = 시간 가동률 × 성능 가동률 × 양품률
   - 계산 예시: 계획 가동 8시간 중 정지 30분, 설계 CT 2분, 실제 생산 200개 중 불량 5개
     → 시간가동률 = (480-30)÷480×100 = 93.75%
     → 성능가동률 = (200×2)÷450×100 = 88.89%
     → 양품률 = (200-5)÷200×100 = 97.5%
     → OEE = 0.9375×0.8889×0.975 = 81.2%

6. **안전율·허용응력 계산**
   - 안전율 = 기준 강도 ÷ 허용 응력 (보통 3~10)
   - 허용 응력 = 기준 강도 ÷ 안전율
   - 계산 예시: 재료의 인장강도 400MPa, 안전율 5
     → 허용 인장응력 = 400÷5 = 80MPa
   - 하중 계산: 압축하중 = 압축응력 × 단면적
   - 계산 예시: 단면적 100mm², 허용압축응력 80MPa
     → 최대 허용 압축하중 = 80×100 = 8,000N

# [실제 수능 기출 예시 — 공일]
EBS 수능특강·수능완성 공업 일반 실제 기출 문항의 톤과 구조를 참고하라.

1. **TPL_COMPARATIVE_MATRIX 예시**
   - 발문: "다음은 A, B, C 세 기업의 생산 방식에 대한 비교 자료이다. 이에 대한 설명으로 옳은 것은?"
   - 표 구성: 기업명(행) × 생산방식·설비배치·적용제품·장단점(열)
   - 자료 특성: 각 기업의 생산 시스템(개별/소량/대량)을 비교하는 표
   - 문제 유형: 생산 방식의 특징을 표 정보와 연결하여 판단

2. **TPL_FORMAL_DOCUMENT 예시**
   - 발문: "다음은 △△공장의 품질 검사 보고서의 일부이다. 이에 대한 분석으로 옳은 것은?"
   - 자료: 품질 검사 항목별 규격치, 측정값, 합격 여부가 포함된 보고서
   - 문제 유형: 검사 결과 해석, 공정 관리 상태 판단, 품질 특성 파악
   - 오답 전략: 검사 항목과 결과의 잘못된 연결, 규격 범위 오해석

3. **TPL_SEQUENTIAL_WORKFLOW 예시**
   - 발문: "다음은 (가)공정의 제조 과정을 나타낸 순서도이다. 이에 대한 설명으로 옳은 것은?"
   - 자료: 원자재 투입 → 가공 → 검사 → 조립 → 출하로 이어지는 5~7단계 순서도
   - 문제 유형: 빈칸 단계의 내용 추론, 단계 간 관계 파악, 공정 흐름 이해
   - 오답 전략: 단계 순서 혼동, 공정 간 기능 오해석

4. **TPL_QUANTITATIVE_CHART 예시**
   - 발문: "다음은 A, B, C 세 제품의 월별 생산량을 나타낸 차트이다. 이에 대한 분석으로 옳은 것은?"
   - 자료: 3개 제품군의 6개월간 생산량 변화를 막대/꺾은선 차트로 표시
   - 문제 유형: 생산 추이 해석, 제품 간 생산량 비교, 증감 원인 추론
   - 오답 전략: 수치 오독, 증감 방향 오해석, 제품 간 비교 오류

5. **TPL_PROMOTIONAL_CANVAS 예시**
   - 발문: "다음은 (가)회사의 신제품 광고이다. 광고에서 강조하는 핵심 메시지로 가장 적절한 것은?"
   - 자료: 제품의 특징·효과·가격·구매처 정보가 포함된 산업용품 광고
   - 문제 유형: 광고의 핵심 전략 파악, 표적 시장 분석, 제품 차별점 인식
   - 오답 전략: 광고에 언급되지 않은 내용을 정답으로 오인, 부차적 정보 선택

6. **TPL_CONVERSATIONAL_FLOW 예시**
   - 발문: "다음은 △△공장 현장 관계자들의 회의 내용 중 일부이다. 회의 내용을 바탕으로 판단할 때 옳은 것만을 <보기>에서 고른 것은?"
   - 자료: 생산팀장·품질관리자·공정엔지니어 간 8~12회 대화문
   - 문제 유형: 대화 속 생산 현안 파악, 각 발언자의 역할과 관점 이해
   - 오답 전략: 특정 발언자의 의견만으로 일반화, 대화 맥락 무시

# [FINAL COMMAND]
**[수량 엄수 - 최우선 규칙]** Blueprint 배열에 포함된 설계도 수와 출력 배열의 문항 수는 반드시 일치해야 한다. Blueprint가 10개면 출력도 반드시 10개다. 단 하나라도 누락하면 시스템 오류로 간주한다. 모든 데이터 집필은 주입된 `text_payload` 내에서만 폐쇄적으로 수행되어야 한다. 위에서 정의된 TPL 인터페이스 스키마를 필드명 하나까지 엄격하게 준수하고, `options_list` 5개와 `correct_answer`를 반드시 포함하여 최종 JSON 배열을 출력하라. 결과물은 React 프론트엔드에서 즉시 매핑하여 사용 가능한 구조여야 한다.

**[수치 계산 문항 작성 시 주의사항]**
1. 자료(stimulus_data)에 계산에 필요한 모든 수치를 명시적으로 포함하라. "적절한 값"이나 "일정 비율" 같은 모호한 표현 금지.
2. 계산 과정이 2단계 이상인 문항은 발문에 "단, ..." 형태로 계산 조건을 명시하라.
3. 오답 선지는 계산 과정의 중간값, 잘못된 공식 적용, 부호 오류 등 현실적인 계산 실수를 반영하라.
4. 수치 계산이 포함된 문항의 정답은 반드시 유일해야 한다. 복수 정답이 발생할 수 있는 모호한 계산 조건을 금지한다.

**[정합성 엄수 - 필수 규칙]** 각 문항을 집필한 후 반드시 아래 3가지를 자체 점검하라:
1. question_stem이 묻는 대상과 options_list가 답하는 대상이 정확히 일치하는가?
2. 조합형 문항의 경우 `render_ready.combo_block`이 존재하며, ㄱ·ㄴ·ㄷ·ㄹ 4개 보기를 모두 포함하는가?
3. 조합형 문항의 경우 ①~⑤가 judgment_map의 truth 조합을 정확히 인코딩하는가?
4. correct_answer에 해당하는 선지가 text_payload 근거에 의해 유일하게 옳은 것인가?
5. `single_selection`이면 5개 선지가 같은 범주의 후보인지 확인하라.
6. `direct_statement`이면 stimulus_data를 읽지 않고는 답할 수 없도록 구성되었는지 확인하라.
7. `blank_workflow`이면 `(가)`/단계/절차와 선지가 직접 대응하는지 확인하라.
8. `exhaustive_subset`이면 combo_block.items가 3개(ㄱ,ㄴ,ㄷ)이고, options_list가 부분집합 조합 5개인지 확인하라.
9. 수치 계산 문항의 경우 모든 계산 과정이 stimulus_data의 수치로부터 도출 가능한지 확인하라. 외부 상식에 의존하는 계산 금지.
10. point_value가 난이도와 일치하는지 확인하라: 하=2, 중=2또는3, 상=3, 극상=3.
위 조건 중 하나라도 위반되면 해당 문항을 즉시 수정하여 출력하라. 정합성 위반 문항을 그대로 출력하면 시스템 오류로 간주한다.
