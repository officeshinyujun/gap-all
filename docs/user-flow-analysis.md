# GAP 사용자 흐름 분석

## 문서 목적

이 문서는 현재 코드베이스를 기준으로 GAP 서비스의 실제 사용자 흐름을 정리한 문서다. 
기획 의도 추정이 아니라, 현재 구현된 라우트와 화면 연결을 바탕으로 사용자의 전체 학습 여정을 구조화하는 데 목적이 있다.

---

## 1. 서비스의 핵심 사용자 흐름 요약

현재 GAP의 중심 UX는 아래 한 문장으로 요약할 수 있다.

> 메인페이지에서 "지금 해야 할 다음 공부"를 제안하고, 사용자는 그 단계로 바로 진입하며, 결과에 따라 진척도/스트릭/복습 필요 항목이 갱신되는 순환 구조

즉 실제 사용자 루프는 다음과 같다.

```text
로그인 → 메인페이지 확인 → 진행중 단원 이어하기 → 개념/문제/시험 수행
→ 오답은 복습으로 회수 → 다시 메인페이지로 복귀
```

---

## 2. 전체 사용자 여정

### 2.1 진입과 인증

- 비로그인 상태에서 메인 영역 접근 시 `/landing`으로 이동
- 랜딩 페이지에서 `시작하기` 클릭
- `/login`에서 로그인 또는 회원가입 수행
- 인증 성공 시 `/` 메인페이지로 이동

흐름:

```text
/landing → /login → /
```

### 2.2 메인페이지의 역할

메인페이지는 단순 홈 화면이 아니라, 사용자의 현재 학습 상태를 요약하고 다음 행동을 제안하는 허브다.

메인페이지에서 노출되는 핵심 정보:

- **study streak**: 연속 학습 일수
- **현재 진행중인 스터디**: 과목/단원별 진행률과 다음 액션
- **복습이 필요해요**: 오답 기반 복습 추천

사용자는 여기서 보통 세 방향으로 이동한다.

1. **이어서 학습하기**
   - 개념 학습하러 가기
   - 빈칸 문제 풀러가기
   - 개념 매칭 풀러가기
   - 연습 시험 보러가기
2. **오답 복습하러 가기**
   - `/review`
3. **사이드바로 직접 이동하기**
   - 과목 학습 `/study/...`
   - 시험 `/exam/...`
   - 채팅 `/chat`
   - 프로필 `/profile`

### 2.3 과목 학습의 메인 루프

과목 학습은 `/study/{subject}`에서 시작한다.

사용 흐름:

1. 과목 선택
2. 단원 선택
3. 단원별 학습 단계 진입
4. 단계별 진척도 저장
5. 메인페이지 또는 과목 페이지로 복귀

### 2.4 단원 학습의 순차 플로우

현재 구현상 단원 학습 순서는 거의 고정되어 있다.

1. **개념 학습**  
   `/study/{subject}/{chapter}/concept`
2. **빈칸 문제**  
   `/study/{subject}/{chapter}/q1`
3. **개념 매칭 문제**  
   `/study/{subject}/{chapter}/q2`
4. **연습 시험**  
   `/study/{subject}/{chapter}/q3`
5. **오답 복습**  
   `/review`

실제 연결 구조:

- `concept` 완료 후 `q1` 이동
- `q1` 결과 후 `q2` 이동
- `q2` 완료 후 과목 페이지 복귀
- `q3` 완료 후 과목 페이지 복귀

즉 한 단원의 대표 학습 흐름은 다음과 같다.

```text
단원 진입 → 개념 읽기 → 빈칸 문제 → 개념 매칭 → 연습 시험 → 과목 목록 복귀
```

### 2.5 진척도와 스트릭의 갱신

각 학습 단계가 끝나면 학습 진척도가 저장되고, 이 데이터는 다시 메인페이지에 반영된다.

대표적으로:

- 개념 학습 완료 시 `BASIC_CONCEPT` 진행도 저장
- 문제 풀이/시험 결과에 따라 각 학습 모드 진행도 저장
- 진행도 저장 시 스트릭도 함께 갱신

그 결과 메인페이지에서:

- 오늘 학습했으면 streak가 반영되고
- 진행중인 스터디의 다음 액션 텍스트가 바뀌며
- 복습 필요 항목도 노출될 수 있다

### 2.6 복습 루프

복습은 일반 학습 루프와는 별도의 약점 보완 흐름이다.

흐름:

1. 학습/시험 중 틀린 개념이 기록됨
2. 메인페이지에 복습 추천 카드가 뜸
3. 사용자가 `/review`로 이동
4. 추천 개념을 단원/개념 단위로 확인
5. 개념 복습 또는 복습용 문제 풀이 수행
6. 결과 제출 후 복습 상태 갱신

장기적으로는 다음과 같은 보완 루프가 형성된다.

```text
새 단원 학습 → 문제 풀이 → 오답 발생 → 복습 추천 → 복습 수행 → 다시 일반 학습
```

### 2.7 시험 기능의 위치

`/exam` 기능은 단원 학습 루프 밖에 있는 별도 평가/문제풀이 채널에 가깝다.

사용 방식:

- 과목별 시험 목록 조회
- 기존 시험 다시 풀기
- 새 시험 생성
- 결과/점수 확인

따라서 `/exam`은 메인 학습 흐름의 연장선이라기보다, **실전 점검용 보조 루프**로 보는 것이 적절하다.

### 2.8 채팅 기능의 위치

`/chat`은 세션 기반 채팅 기능으로, 메인 학습 루프 자체보다는 학습 중 막히는 부분을 보조하는 도우미 역할에 가깝다.

예상 사용 흐름:

```text
공부하다가 질문 발생 → 채팅에서 질문 → 다시 학습/시험으로 복귀
```

### 2.9 프로필 기능의 현재 위치

현재 프로필 페이지는 일부 데이터가 하드코딩된 상태라서, 지금 시점에서는 핵심 사용자 루프의 중심이라기보다 추후 리포트/계정 관리용 페이지에 더 가깝다.

## 3. 3가지 대표 사용자 시나리오

현재 구조를 기준으로 사용자 흐름을 다음 3가지 대표 시나리오로 나눌 수 있다.

---

### 3.1 신규 유저 시나리오

이 시나리오는 서비스에 처음 들어온 학생이 **서비스를 이해하고, 가입하고, 첫 학습을 시작하는 흐름**이다.

#### 흐름

1. 랜딩 페이지 진입 (`/landing`)
2. `시작하기` 클릭 후 로그인/회원가입 페이지 이동 (`/login`)
3. 회원가입 또는 로그인 완료
4. 메인페이지 진입 (`/`)
5. 진행중인 스터디가 없으면 과목 페이지로 이동
6. 과목 선택 (`/study/success` 또는 `/study/industry`)
7. 단원 선택 후 첫 학습 시작
8. `concept → q1 → q2 → q3` 순으로 첫 루프 수행

#### 핵심 목적

- 서비스 구조를 이해한다
- 어디서부터 공부를 시작해야 하는지 안내받는다
- 첫 진척도를 만든다

#### 제품적으로 중요한 포인트

- 메인페이지 빈 상태 안내
- 첫 과목/첫 단원 진입 유도
- 진입 장벽 없이 첫 학습을 시작하게 만드는 것

---

### 3.2 재방문 유저 시나리오

이 시나리오는 이미 학습 이력이 있는 사용자가 **이전에 하던 공부를 바로 이어서 하는 흐름**이다.

현재 서비스의 핵심 시나리오에 가장 가깝다.

#### 흐름

1. 앱 재접속
2. 토큰 유지 상태면 자동 로그인
3. 메인페이지 진입
4. 스트릭, 진행중인 스터디, 복습 필요 여부 확인
5. 진행중인 스터디 카드에서 다음 액션 클릭
6. 마지막 진행 상태에 맞는 학습 단계로 즉시 이동
7. 학습 완료 후 메인 또는 과목 페이지 복귀

#### 대표 액션 예시

- 개념 학습하러 가기
- 빈칸 문제 풀러가기
- 개념 매칭 풀러가기
- 연습 시험 보러가기

#### 핵심 목적

- 어디까지 했는지 다시 기억하지 않아도 됨
- 바로 이어서 공부할 수 있어야 함

#### 제품적으로 중요한 포인트

- 메인페이지가 재진입 허브로 잘 작동해야 함
- 진행도 기반 액션 텍스트가 정확해야 함
- 사용자가 클릭 한 번으로 다음 학습 단계로 이동해야 함

---

### 3.3 복습 중심 유저 시나리오

이 시나리오는 새로운 단원 학습보다, **틀렸던 개념을 다시 보완하는 데 집중하는 흐름**이다.

#### 흐름

1. 메인페이지 진입
2. `복습이 필요해요` 카드 확인
3. `/review` 진입
4. 추천 복습 목록 확인
5. 취약 개념 중심 복습 수행
6. 복습 결과 제출
7. 복습 필요 항목 감소 또는 상태 갱신
8. 메인페이지 복귀 또는 일반 학습 복귀

#### 핵심 목적

- 약한 개념만 빠르게 다시 잡는다
- 불필요한 반복 없이 부족한 부분만 회복한다

#### 제품적으로 중요한 포인트

- 복습 추천의 우선순위가 납득 가능해야 함
- 복습 동선이 일반 학습보다 더 짧고 명확해야 함
- 결과 제출 후 상태 변화가 체감되어야 함

---

## 4. 3가지 시나리오 비교

| 시나리오 | 시작점 | 주 행동 | 종료 지점 | 핵심 가치 |
|---|---|---|---|---|
| 신규 유저 | 랜딩/회원가입 | 첫 단원 시작 | 과목/메인 | 처음 시작하기 쉽게 |
| 재방문 유저 | 메인페이지 | 하던 공부 이어하기 | 메인/과목 | 끊김 없이 이어하기 |
| 복습 중심 유저 | 메인 복습 카드 | 약점 개념 보강 | 리뷰/메인 | 틀린 부분만 빠르게 회복 |

---

## 5. 현재 서비스의 중심 시나리오 판단

현재 구현 상태 기준으로, 이 서비스의 중심 시나리오는 아래 우선순위로 보인다.

1. **재방문 유저 시나리오**
2. **복습 중심 유저 시나리오**
3. **신규 유저 시나리오**

이유는 다음과 같다.

- 메인페이지가 현재 상태 요약과 재진입 유도를 중심으로 설계되어 있음
- 진행도 기반 다음 액션이 구현되어 있음
- 복습 추천이 별도 루프로 준비되어 있음
- 반면 신규 유저 온보딩은 상대적으로 단순함

즉 현재 GAP은 “가입을 시키는 서비스”보다, **이미 학습 중인 학생이 매일 다시 돌아와서 이어서 공부하고, 약점을 복습하게 만드는 서비스**에 더 가깝다.

---

## 6. 결론

현재 GAP의 사용자 여정은 다음과 같이 해석할 수 있다.

- **신규 유저**는 첫 학습을 시작하기 위한 진입 흐름을 밟는다.
- **재방문 유저**는 메인페이지를 중심으로 이전 학습의 다음 단계에 빠르게 복귀한다.
- **복습 중심 유저**는 오답 기반 추천을 통해 약한 개념을 우선적으로 보완한다.

결국 서비스 전체는 아래 루프로 수렴한다.

```text
로그인 → 메인페이지 → 다음 학습 단계 진입 → 진척도 저장 → 복습 필요 항목 생성/해소 → 메인페이지 복귀
```

이 구조를 기준으로 이후 UX 개선, 온보딩 개선, 메인페이지 CTA 개선, 복습 흐름 강화 작업을 설계할 수 있다.

---

## 7. UX 병목 포인트

현재 구현된 사용자 흐름은 전체 방향이 명확하지만, 실제 사용성 관점에서는 몇 가지 병목이 보인다. 
특히 신규 유저의 첫 진입, 재방문 유저의 재개 동선, 복습 루프의 이해 가능성에서 마찰이 생길 가능성이 높다.

### 7.1 신규 유저가 첫 공부를 시작하는 진입점이 약하다

#### 문제

- 신규 유저는 로그인 직후 메인페이지로 들어오지만, 진행 데이터가 없으면 메인에서 바로 행동할 수 있는 CTA가 약해질 수 있다.
- 서비스의 핵심은 `/study` 학습 루프인데, 처음 들어온 유저에게 “무엇부터 해야 하는지”를 아주 직접적으로 밀어주지는 않는다.

#### 왜 병목인가

신규 유저는 서비스를 아직 이해하지 못한 상태라서, 선택지가 많을수록 오히려 멈춘다.
메인페이지가 기존 사용자에게는 재진입 허브로 잘 작동하지만, 신규 유저에게는 빈 상태 대시보드처럼 느껴질 수 있다.

#### 예상 사용자 반응

- “그래서 지금 뭘 눌러야 하지?”
- “성직이랑 공일 중 뭘 먼저 해야 하지?”
- “개념부터 해야 하는 건가, 문제부터 풀어도 되나?”

#### 개선 방향

- 진행중인 스터디가 없을 때만 보이는 **첫 학습 시작 CTA** 추가
- 예: `첫 단원 시작하기`, `성공적인 직업생활 1단원 시작`, `추천 학습 시작`
- 메인페이지에서 신규 유저용 안내 문구를 별도로 노출

---

### 7.2 메인페이지의 "진행중인 스터디"는 좋지만, 왜 그 액션인지 설명이 없다

#### 문제

- 현재는 진행도 기반으로 `개념 학습하러 가기`, `빈칸 문제 풀러가기` 같은 액션 텍스트가 잘 바뀐다.
- 하지만 사용자는 왜 지금 이 단계가 추천되는지, 이전 단계는 끝난 것인지 직관적으로 알기 어렵다.

#### 왜 병목인가

재방문 유저는 “이어하기” 자체는 편하게 느끼지만, 학습 맥락이 짧게라도 보이지 않으면 추천을 신뢰하기 어렵다.
특히 며칠 뒤 다시 들어온 경우에는 “내가 개념은 했고 빈칸만 남은 건지, 아니면 그냥 여기로 보내는 건지”를 헷갈릴 수 있다.

#### 예상 사용자 반응

- “왜 갑자기 q2로 가라고 하지?”
- “내가 여기까지 했던가?”
- “개념은 다 끝난 상태인지 모르겠네”

#### 개선 방향

- 카드에 현재 단계 정보 추가
  - 예: `개념 완료 · 빈칸 진행중`
  - 예: `다음 단계: 개념 매칭`
- 또는 작은 progress step UI 추가
  - 개념 / 빈칸 / 매칭 / 시험

---

### 7.3 과목 페이지의 학습 단계 구조는 보이지만, 추천 진입점이 분산되어 있다

#### 문제

- 메인에서는 “다음 단계”로 바로 들어가게 하고,
- 과목 상세 페이지에서는 단원 카드와 세부 subUnit이 보인다.
- 그런데 사용자가 과목 페이지로 직접 들어왔을 때, 가장 추천되는 다음 행동이 메인만큼 강하게 드러나지 않을 수 있다.

#### 왜 병목인가

사용자가 메인이 아니라 사이드바를 통해 직접 `/study/{subject}`로 들어오면, 다시 단원 선택과 단계 선택을 머릿속으로 해석해야 한다.
즉 메인에서는 개인화된 재개 UX가 있고, 과목 페이지에서는 정보 탐색 UX가 강해서 경험 톤이 약간 갈린다.

#### 개선 방향

- 선택된 단원 detail 영역에 **추천 다음 액션 버튼**을 더 명확히 배치
- 예: `이어서 빈칸 문제 풀기`, `다음 추천 단계 시작`
- 단원별로 “최근 학습 위치”를 문장으로 보여주기

---

### 7.4 복습 루프는 중요하지만, 메인 학습과의 관계가 사용자에게 명확하지 않다

#### 문제

- 메인페이지에 `복습이 필요해요` 카드가 뜨고 `/review`로 이동할 수 있다.
- 하지만 복습이 일반 학습 흐름과 어떤 관계인지, 지금 복습을 먼저 해야 하는지, 나중에 해도 되는지 판단 기준이 화면상 명확하지 않을 수 있다.

#### 왜 병목인가

복습은 매우 중요한 루프지만, 타이밍이 애매하면 사용자는 이를 “중간에 끼어드는 별도 기능”으로 느낄 수 있다.
특히 진행중 스터디와 복습 카드가 동시에 보이면, 무엇을 우선해야 하는지 혼란이 생길 수 있다.

#### 예상 사용자 반응

- “일단 진도부터 나가야 하나, 복습부터 해야 하나?”
- “이 복습을 안 하면 다음 공부에 문제 생기나?”

#### 개선 방향

- 복습 카드에 우선순위 힌트 추가
  - 예: `최근 틀린 개념이라 먼저 복습하는 걸 추천해요`
  - 예: `지금은 진도보다 복습이 더 중요해요`
- 또는 메인에서 `오늘의 우선순위` 개념으로 재정렬

---

### 7.5 학습 완료 후 다음 행동 유도가 약하게 끊기는 구간이 있다

#### 문제

- `q2`, `q3` 완료 후에는 과목 페이지로 돌아가며 `학습 완료 →` 형태로 마무리된다.
- 하지만 사용자는 완료 직후 “다음에 무엇을 해야 하는지”를 강하게 이어받지 못할 수 있다.

#### 왜 병목인가

학습 세션의 끝은 다음 행동을 설계하기 가장 좋은 순간인데, 여기서 흐름이 약해지면 사용자는 학습을 종료하거나 이탈하기 쉽다.

#### 개선 방향

- 완료 화면에서 다음 제안 추가
  - 다음 단원 시작
  - 복습하러 가기
  - 메인으로 돌아가기
- 결과 화면을 단순 종료가 아니라 **다음 행동 선택 화면**으로 바꾸기

---

### 7.6 프로필 페이지는 전체 서비스 흐름에서 역할이 약하다

#### 문제

- 프로필 페이지는 현재 하드코딩 데이터 비중이 높고, 실제 학습 흐름과 강하게 연결되어 있지 않다.
- 사용자가 프로필에 들어가도 “다음 공부 행동”으로 이어지기 어렵다.

#### 왜 병목인가

프로필은 학습 리포트나 동기부여 공간이 될 수 있는데, 지금 상태에선 메인 흐름 바깥의 정적 화면처럼 느껴질 가능성이 있다.

#### 개선 방향

- 실제 데이터 기반 학습 리포트 연결
- 프로필에서 바로 `이어서 공부하기`, `복습하러 가기` CTA 제공

---

### 7.7 채팅 기능은 존재하지만, 학습 흐름 안에서 호출 타이밍이 보이지 않는다

#### 문제

- `/chat`은 세션 기반 보조 도구로 존재하지만, 학습 중 언제 쓰면 좋은지 화면상으로 드러나지 않는다.
- 사용자가 채팅 기능을 발견하더라도 학습 맥락과 연결하기 어렵다.

#### 왜 병목인가

좋은 보조 도구라도 메인 학습 루프 안에 자연스럽게 삽입되지 않으면 사용률이 떨어질 수 있다.

#### 개선 방향

- 개념/문제 화면에서 `이 부분 질문하기` 같은 진입점 제공
- 채팅을 독립 기능이 아니라 학습 지원 기능으로 재배치

---

## 8. 우선순위 높은 UX 병목 정리

현재 기준으로 우선적으로 해결 가치가 높은 병목은 아래 4가지다.

1. **신규 유저 첫 학습 시작 진입점 부족**
2. **진행중인 스터디 액션의 추천 근거 부족**
3. **복습과 일반 학습 사이의 우선순위 혼란**
4. **학습 완료 직후 다음 행동 유도 부족**

이 4가지는 실제 학습 지속률과 재방문 경험에 직접 영향을 줄 가능성이 높다.

---

## 9. 요약

현재 GAP의 정보 구조는 전반적으로 잘 잡혀 있다.
특히 메인페이지 중심의 재진입 구조, 단원별 순차 학습, 오답 복습 루프는 방향성이 분명하다.

다만 UX 병목은 대부분 **"다음 행동은 존재하지만, 그 행동의 맥락과 우선순위가 충분히 설명되지 않는 지점"**에서 발생한다.

즉 앞으로의 UX 개선은 새로운 기능을 늘리는 것보다 아래 3가지에 집중하는 것이 효과적이다.

- 처음 시작할 때 덜 헤매게 하기
- 다시 들어왔을 때 더 확신 있게 이어가게 하기
- 복습과 다음 행동의 우선순위를 더 분명히 보여주기
